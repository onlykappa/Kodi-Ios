# Agent instructions: Kodi iOS

Instructions for every coding agent working in this repository (Codex, Claude Code and others). `CLAUDE.md`
imports this file. The rules here summarise and point to existing project documents. Where a summary is shorter
than its source, the source governs.

## Project

A customized Kodi 21.3 (Arctic Fuse 3) for an unsigned iPhone IPA: a portrait skin generated by Python,
bundled add-ons, Google Drive, AirPlay conversion and a native tab bar. See [README.md](README.md).

## Session protocol (from ROADMAP.md)

- Resume by reading [ROADMAP.md](ROADMAP.md), [docs/PROGRESS.md](docs/PROGRESS.md), [docs/ISSUES.md](docs/ISSUES.md)
  and [docs/DECISIONS.md](docs/DECISIONS.md). Then inspect the branch, recent commits and open PRs. Do not infer
  completion from chat.
- Work loop: Inspect → Plan → Implement → Test → Diagnose → Fix → Retest → Document → Commit → Update roadmap.
  Log failures in `docs/ISSUES.md` with root cause, fix, retest and regression protection. Never erase failures.
- Device behaviour needs the owner's actual iPhone evidence. Host checks, builds and rigs never prove phone results.
- **Never merge, release or publish an IPA without explicit owner approval** in the current request (see DECISIONS).
  Work happens on a feature branch with a PR to `main`. ROADMAP's "Only feature/ios-migration" line predates the
  version-1 merge (DEC-024). Since then each piece of work has its own branch and PR.
- Private backups, keys, tokens, account state, Drive IDs, logs and media stay outside Git.
  `python3 -B scripts/check_project.py` must pass before committing.

## UI work: mandatory

**Before planning, implementing or reviewing any UI change**, read the canonical policy
**[docs/design/APPLE-UI-POLICY.md](docs/design/APPLE-UI-POLICY.md)**. UI change here means layout, styling,
navigation, controls, typography, icons, artwork, animation, player overlays, sheets, settings, notifications,
the activity pill or sheet, loading, empty or error states, the native tab bar, or design mockups.

Then load only what its routing table (§3) names from:

- `.agents/skills/apple-hig/`: Apple HIG reference (vendored, pinned). Entry: `SKILL.md`, then `routing-index.md`.
- `.agents/skills/apple-liquid-glass/`: native UIKit Liquid Glass only (`KodiGlassBar`).
- `.agents/skills/kodi-ios-ui/SKILL.md`: the project entry point that routes to the two above.

Key points (the policy has the detail):

- This app's UI is mostly **Kodi skin XML**, not SwiftUI/UIKit. Only the tab bar and search field are native.
  Kodi-drawn translucency is a static texture, never "Liquid Glass".
- Reuse existing helpers and tokens (`portrait.py`, `pages.py`) before adding variants.
- Follow the visual review process (policy §7) and label screenshots as mockup, desktop Kodi rig or device
  (policy §9). A passing check is not visual verification.
- To see a page in real Kodi, use the desktop Kodi rig: `python3 -B scripts/kodi_rig.py setup` once (builds Kodi
  21.3, about 15 min), then `start` and `boards` (every approved board next to its mockup). Guide:
  [docs/design/KODI-RIG.md](docs/design/KODI-RIG.md). Rig screenshots never go into Git.
- Apple's current documentation outranks every vendored summary.

Skill discovery: Codex scans `.agents/skills/`. Claude Code reads `.claude/skills/`, which holds pointers to the
same files. Other agents must read the paths above directly. Provenance, pinned revisions and the update procedure
are in [docs/design/apple-ui-resources.md](docs/design/apple-ui-resources.md). Run
`python3 -B scripts/check_ui_guidance.py` after changing any of these files.
