# Metadata outages: TMDb and ESPN (roadmap step 20)

Code: `source_match.py` (`tmdb_get`, `enrich`, `STALE_TTL`, the `metadata` field) and `sports_match.py` (`as_of`, `LIVE_SNAPSHOT_MAX`). Tests: `scripts/test_metadata_snapshot.py` (8 tests, host only).

**TMDb.** The existing cache (a week) already served repeat lookups. Now, when TMDb cannot be reached (or there is no key), an older answer up to 90 days old is still used instead of nothing, and `enrich` marks the result: `exp['metadata']` is `live` (fetched now), `cached` (fresh cache), `stale` (an answer older than a week used because TMDb was unreachable) or `none` (no TMDb facts at all). The flag is per call. A title with a prior snapshot keeps matching strictly through an outage: the aliases, the release years and the "another film has this title" answer all come from the snapshot (tested: the right year passes, the 2026 film and "Free Fall" do not). A title never seen, or an answer older than 90 days, fails safe: `none`, a name with no year is hidden because nothing can say no other film shares the title, and an exact title-plus-year name still passes (the strict check is unchanged). No claim that stale metadata is correct: a renamed or new release is only picked up once TMDb answers again.

**ESPN (Sports).** The ESPN snapshot (up to 48 h) was already drawn as remembered. `sports_match` now takes the snapshot's age (`as_of`): a remembered "live" game older than 15 minutes is `stale` (its state and score are unknown), so no source is matched or started for it; an upcoming game from an old snapshot is still fine until its start has passed by hours; a live fetch (no `as_of`) behaves as before. The step 10 rules (8 h live limit, unknown states, finished games) still apply.

**Not done.** Nothing shows the person that a title's data is stale (`metadata` is only a field; a visible hint would be UI work for the end). The snapshot is the existing cache file (no separate pre-fill of titles you have not looked up yet). The Sports screens still call `sports_espn` as before and do not pass `as_of` yet.
