# Own AllDebrid account and debrid-failure detection (roadmap step 17)

Code: `migration/bundled-bootstrap/resources/lib/debrid_account.py`, with `alldebrid.py` (errors now carry AllDebrid's code and a failure kind; an optional `observe` hook) and `debrid_token.py` (`save_own`, `clear`, `own`). Tests: `scripts/test_debrid_account.py` (16 tests, host only, against a fake service).

**Sign-in (PIN flow).** Follows AllDebrid's documented flow (docs.alldebrid.com, read 2026-11-26): `GET /v4.1/pin/get` gives a short pin and the page to open; the app shows them, then polls `POST /v4/pin/check` every 5 s (at most 10 minutes, or the pin's own expiry) until the key arrives. The key is saved only in the app's profile (owner-only file plus a marker that it outranks Umbrella's setting) and never printed, logged or put in health records (tested). Cancel stops the polling; an expired pin is `expired`. `sign_out` removes the app's key; Umbrella's own setting is untouched and is used again if it still holds one.

**Typed errors.** Every AllDebrid error code in the documented list maps to one outcome: key missing/bad, premium needed, trial used up -> `account-required`; geo/IP block, banned, too many active magnets or downloads -> `refused`; maintenance, no server, host full -> `offline`; unknown or removed magnet/link, expired pin -> `expired`; invalid magnet/torrent, too large -> `unsupported`; "not downloaded in 20 min" -> `empty`. An unknown or missing code is `unsupported`; a network failure is `offline`, a timeout `timeout`, HTTP 403/429/451 with no body `refused`. A magnet that is simply not cached is not an error (the API says `ready` is false): no penalty.

**"Debrid is unavailable".** Every AllDebrid call made through the client now reports its result (`observe`) into the shared source health under the name `debrid`. `unavailable()` is true only after 3 consecutive service-level failures (offline, timeout, refused) that are still cooling down; account problems, one bad title and not-cached answers never flip it; one success clears it; it ends by itself with the cooldown. Step 18 reads this to offer the direct route. The service's download queue (`service.py`) is wired to report; the Umbrella link-renewal call is not.

**Not done.** There is no screen for signing in or out yet (it needs a UI design under the Apple UI policy and a rig look, planned for the end); sign-in is only reachable from code and tests. The real AllDebrid service was not contacted and the live PIN and error shapes are as documented, not observed. No device evidence.
