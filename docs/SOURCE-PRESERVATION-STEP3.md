## Concrete remaining blockers and decisions

1. **Durable trusted backup is not established.** The 29 files were freshly retrieved from upstream and exist only in disposable scratch. The existing provider fetch command requires its URLs unless a caller supplies a local mapping; the Elementum fetcher also requires a framework release, AirPlay framework, and sparse Git checkouts unless separately supplied. A warm download is not an owner-controlled archive and does not prove clean restoration after its loss.
2. **Storage choice:** after file-by-file license and notice review, small approved source/notice material could live in the private repository; large approved artifacts should use an owner-controlled, access-restricted artifact store with immutable digest-addressed copies, retention/backups and a documented retrieval procedure. A private GitHub release would be one possible store but is expressly not authorized in this task; no release or external upload was made. The owner needs to identify an existing permitted artifact location or authorize a concrete storage mechanism after the eligible inventory is reviewed.
3. **Unresolved inputs:** obtain and verify the exact Elementum framework, source and pinned Git module trees; audit their transitive native build inputs and notices. Resolve the Burst/client manifest contradictions, third-party artwork terms and Otaku database license. Complete the Umbrella package provenance separately. Do not store or distribute items whose authorization or rights remain unresolved.
4. **Runtime closure:** rebuild the isolated Kodi 21.3 profile if its executable/prefix can be recovered, install the newly staged current manifests with services treated explicitly, and test actual Crew runtime imports. Static manifest closure alone cannot establish ISSUE-398 is fixed at runtime or on the phone.
5. **No availability promise:** package preservation cannot preserve external discovery sites, Crew's remote modules, ESPN, accounts, debrid APIs, content endpoints, trackers or peers. Step 3 does not implement independent discovery; steps 4–16 remain unstarted.

Until an approved persistent copy exists and a clean restore from it is exercised with source hosts unavailable, step 3's preservation acceptance is **blocked**, not complete. No production playback code, IPA, release, engine publication or merge is included.
