## Licensing and distribution boundaries

The included Elementum client and Burst archives each contain an MIT LICENSE attributed to elgatito. The client also contains a separate icon-attribution file referring to CC BY 3.0 and other icon sources; preserve and review those terms independently. Burst's manifest says WTFPL while its bundled LICENSE says MIT: the inconsistency needs upstream/source-level clarification before asserting a single license for every included file. Elementum's manifest similarly states non-commercial while its included LICENSE says MIT. These observations are evidence, not a legal determination for the entire archives.

The inspected Crew plugin, Crew module, ResolveURL, CocoScrapers and Crew artwork archives have no separate top-level LICENSE/COPYING/NOTICE file found by filename; Crew/Coco manifests or retained source headers declare GPL, while the provider lock supplies a verified GPL-3.0 text for the shipped notices. Individual file headers, third-party artwork, optional assets and complete corresponding-source obligations need review before treating those packages as approved for redistribution. `otaku-mappings.db` is pinned and contains public identifiers, but its lock records no separate upstream license declaration; a successful test is not permission to mirror it.

First-party coordinator, scripts, locks and fixture tests are already in this repository; retain their history and source. Do not create another native torrent engine: the Elementum framework, client, Burst, module-tree revisions and native build inputs are already described by `migration/elementum-ios/source-lock.json`, but the pinned framework artifact and its build dependency closure were not recovered or tested offline in this exercise.

## Concrete remaining blockers and decisions

1. **Durable trusted backup is not established.** The 29 files were freshly retrieved from upstream and exist only in disposable scratch. The existing provider fetch command requires its URLs unless a caller supplies a local mapping; the Elementum fetcher also requires a framework release, AirPlay framework, and sparse Git checkouts unless separately supplied. A warm download is not an owner-controlled archive and does not prove clean restoration after its loss.
2. **Storage choice:** after file-by-file license and notice review, small approved source/notice material could live in the private repository; large approved artifacts should use an owner-controlled, access-restricted artifact store with immutable digest-addressed copies, retention/backups and a documented retrieval procedure. A private GitHub release would be one possible store but is expressly not authorized in this task; no release or external upload was made. The owner needs to identify an existing permitted artifact location or authorize a concrete storage mechanism after the eligible inventory is reviewed.
3. **Unresolved inputs:** obtain and verify the exact Elementum framework, source and pinned Git module trees; audit their transitive native build inputs and notices. Resolve the Burst/client manifest contradictions, third-party artwork terms and Otaku database license. Complete the Umbrella package provenance separately. Do not store or distribute items whose authorization or rights remain unresolved.
4. **Runtime closure:** rebuild the isolated Kodi 21.3 profile if its executable/prefix can be recovered, install the newly staged current manifests with services treated explicitly, and test actual Crew runtime imports. Static manifest closure alone cannot establish ISSUE-398 is fixed at runtime or on the phone.
5. **No availability promise:** package preservation cannot preserve external discovery sites, Crew's remote modules, ESPN, accounts, debrid APIs, content endpoints, trackers or peers. Step 3 does not implement independent discovery; steps 4–16 remain unstarted.

Until an approved persistent copy exists and a clean restore from it is exercised with source hosts unavailable, step 3's preservation acceptance is **blocked**, not complete. No production playback code, IPA, release, engine publication or merge is included.

## Follow-up: owner prefers an in-app backup

The owner is comfortable keeping the eventual usable backup on the device or in the app. That addresses runtime availability but does not itself provide the licensed, durable build inputs needed to reconstruct a fresh app if upstream packages disappear. These tests do not increase app size or modify the existing engine. The current provider archives include the approximately 42 MB artwork package; this is an input size, not a measurement of added IPA size.

The pinned 10,372,968-byte Elementum framework release was downloaded and its SHA256 matched the existing lock. All five pinned Git module trees were fetched from their locked commits and their exact Git tree hashes independently matched by creating local Git indexes. The five manifests declare MIT, GPL-2.0-or-later or GPL v3 and each tree contains a license file; bundled image and other third-party file terms still require inspection. The four pinned extras and the pinned AirPlay framework also matched their locks.

`python3 -B scripts/source_elementum_offline.py --inputs <verified-inputs> --output <empty-directory>` then passed the local blobs to the existing `fetch_elementum_inputs.run`, checked all five module Git tree hashes locally, and staged the client, Burst, existing Elementum framework, AirPlay framework, and four extras. Python socket connects were blocked in that process; its `git init`, `git add`, and `git write-tree` subprocesses were local operations, not a network firewall. This does not validate iOS execution, native rebuild dependencies or a durable backup. `test_source_offline_restore.py` also checks a synthetic tree change is rejected. An attempted `test_fetch_elementum_inputs.py` invocation failed because that file does not exist; the actual related tests are in `test_updates_calibration.py`.

**Still blocked:** the verified inputs remain in disposable scratch and are not approved durable copies. `check_project.py` and `.gitignore` currently reject archives, binaries and large files, so Git LFS adoption needs a narrow, reviewed verification and scanning policy rather than bypassing the checks. The earlier license/artwork/mapping questions, complete native build-source closure and actual Kodi runtime validation remain open. No profile, archives, binaries, release or IPA has been committed.
