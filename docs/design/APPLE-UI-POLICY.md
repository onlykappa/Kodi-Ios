# Kodi iOS Apple UI policy

This is the **canonical UI policy** for Kodi iOS. `AGENTS.md`, `CLAUDE.md` and the project skill
`kodi-ios-ui` all point here. If they ever disagree with this file, this file wins. If this file disagrees
with Apple's current documentation, Apple's documentation wins (see [Authority](#1-authority)).

Adopted 2026-11-05 (DEC-026). The vendored resources and their pinned revisions are listed in
[apple-ui-resources.md](apple-ui-resources.md).

## 0. When this policy applies

**Read this file before you plan or implement** any change that touches:
layout, styling, navigation, controls, typography, icons, artwork, animation, player overlays, sheets,
settings pages, loading/progress, empty states or error states. This includes reviews of such changes, the
activity pill and sheet, the Notifications page, the native tab bar and HTML mockups in `docs/design/`.

Pure back-end changes (Drive, AirPlay conversion, Elementum, packaging) that alter no visible text or
layout do not need it. Changing a visible string or progress line does.

## 1. Authority

In order of precedence:

1. **Apple's current documentation**: the [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines)
   and the [Apple Developer Documentation](https://developer.apple.com/documentation). Check the live page when a
   vendored summary is ambiguous, conflicts with another source, or concerns API availability.
2. **This policy**: project decisions that apply Apple guidance to Kodi's renderer.
3. **Vendored community skills**, as summaries of (1):
   - `apple-hig` ([.agents/skills/apple-hig/SKILL.md](../../.agents/skills/apple-hig/SKILL.md)). It distils the HIG and was source-reviewed by its author against Apple's 2026-09-12 snapshot.
   - `apple-liquid-glass` ([.agents/skills/apple-liquid-glass/SKILL.md](../../.agents/skills/apple-liquid-glass/SKILL.md)). Native Liquid Glass APIs only.
4. **Kodi implementation references** ([apple-ui-resources.md](apple-ui-resources.md#kodi-implementation-reference)):
   these show how to do things in Kodi XML. They are not design authority.

Community material is not Apple's. When it conflicts with Apple's pages, follow Apple and note the conflict in
your report.

## 2. The real UI architecture (know which renderer you are in)

| Surface | Technology | Where | What is possible |
|---|---|---|---|
| Portrait pages (Home, Movies, TV, Library, Search, show/info pages, More, Notifications, Settings, select/context dialogs, activity pill/sheet) | **Kodi 21.3 skin XML**, generated by Python at runtime | `migration/bundled-bootstrap/resources/lib/portrait.py`, `pages.py`, `settings_page.py` (+ PR #9 `activity*.py`) | Kodi controls only: images, labels, buttons, lists, grouplists; static PNG textures; `colordiffuse`; animations (fade/slide/zoom/rotate with tween + easing). **No live blur, refraction, vibrancy, Dynamic Type or SF Symbols.** |
| Landscape pages and video OSD | Arctic Fuse 3 1080i XML, patched | Fuse skin + `pages.py` wrappers | Same Kodi limits; Fuse's own look. Do not restyle Fuse wholesale. |
| Portrait tab bar and native Search field | **UIKit (Objective-C)**, `KodiGlassBar.framework` | `migration/glassbar-ios/build-glassbar.sh`, driven by `glassbar.py`/`native_ui.py` and Kodi r22+ | Real system materials: `UIGlassEffect` (Liquid Glass, iOS 26+) with `UIBlurEffect` fallback. Native accessibility settings apply. |
| Kodi engine changes (rotation, touch, scrolling) | C++ patch to Kodi | `migration/ios-portrait/kodi-21.3-portrait.patch` | Behaviour, not styling. Needs a native build and pin. |
| Design mockups | Self-contained HTML | `docs/design/*.html` | Browser rendering only. **Not evidence of the app.** |

There is **no SwiftUI** in this project. SwiftUI guidance does not make SwiftUI APIs available inside Kodi.
Do not replace the architecture, switch skins or add a native wrapper unless the owner has decided to (that
needs a DECISIONS entry).

### Glass: say exactly what it is

- **Native Liquid Glass** exists in only one place: `KodiGlassBar` uses `UIGlassEffect`, available on iOS/iPadOS 26.0+
  ([Apple docs](https://developer.apple.com/documentation/uikit/uiglasseffect), verified 2026-11-05). On older iOS it falls back to a system blur material.
- Everything Kodi draws that looks frosted (`portrait.glass()`, `glass_*.png`, `pill_*.png`) is a **static
  translucent texture**. It does not blur, refract or adapt to what's behind it. Call it a "glass-styled surface"
  in code, docs and reports. **Never call it Liquid Glass.**
- Because Kodi glass cannot blur, artwork shows through at full detail and fights the text. Glass-styled surfaces
  that carry text must be **at least about 90 % opaque** over artwork or lists. PR #9 found this: the see-through
  pill became almost opaque.

## 4. Visual system (Kodi iOS look)

**Direction (owner):** dark backgrounds, artwork-led heroes, clear white typography, restrained blue accents,
rounded action buttons, horizontal media rows, a compact floating activity control and a larger activity sheet.
It should be content-first, with chrome that recedes.

**Reference screenshots (device class, owner, 2026-11-05; not committed because they contain film artwork).**
The owner supplied them after this policy was first written. They show the current app:

1. **Movies tab with the activity pill.** Shows a full-bleed hero with a title logo, a "Crime · 2008 · PG-13" meta line,
   a white capsule Play button next to a dark capsule Info button, and page dots. Below come "Continue Watching ›"
   16:9 cards with year and title, then a "Popular Movies ›" poster row. The floating activity pill sits above the
   native tab bar (Home · Movies · TV · Library · Search), with Movies tinted blue.
2. **The same page with the Activity sheet open.** The page is dimmed. There is a bell with a red "3" badge and a
   blue progress arc, plus a profile circle. The sheet has a grabber, a large "Activity" title and a blue "Done".
   Each row has a blue app tile, a title, a "4K · 20.9 MB/s · 5 min left" line, a thin blue progress bar and a
   round pause button.

These screens are the target look: keep the structure and style, and fix the defects in ISSUE-102. They are
aesthetic references, not specifications, and not permission to add features. Never copy film artwork, logos,
branding or fonts from them. Screenshot measurements use 920 px = 402 pt (2.29 px/pt) and are approximate.

### 4.1 Units: points to Kodi coordinates

The portrait skin canvas is **1080 × 2090** units. It maps to the iPhone 16 Pro's portrait safe area of 402 × 778 pt,
so the scale is **2.687 units per pt** (`portrait.py`). Convert every HIG value with this scale:

| HIG value | pt | Kodi portrait units |
|---|---:|---:|
| Minimum hit region | 44 × 44 | **118 × 118** |
| Standard side margin | 20 | 54 (`SIDE`) |
| Spacing steps | 4 / 8 / 12 / 16 / 24 / 32 | 11 / 21 / 32 / 43 / 64 / 86 |
| Body text | 17 | 44–46 |
| Minimum text | 11 | 30 (`p_cap`): never smaller |

Landscape uses Fuse's 1920 × 1080 canvas, which Kodi stretches into the landscape safe area. Compute that scale
from the actual safe area; do not reuse 2.687. Native UIKit code uses points directly.

### 4.2 Typography

Use the `FONTS` table in `portrait.py`. Its sizes are HIG text styles at 2.687 units/pt: large title 34 pt → 92,
title 78, title2 → 58, headline/body 44–46, subhead 40, footnote 35, caption 30.

- **Font: Inter (SIL OFL).** Apple's SF fonts may not be bundled into this app. Kodi cannot reach the system font,
  so Inter is the approved substitute. Never add SF font files.
- Hierarchy comes from size and weight, not from boxes and borders. Use at most three text sizes per component.
- Titles: white. Secondary text: `GREY` (60 %). Tertiary `DIM` (30 %) is **not readable text** (see §6).
- **No two text runs may overlap.** If two labels share a line, the leading label's width must end before the
  trailing label starts (or use a single label / an auto-width grouplist). Every label that can receive
  variable-length text needs an explicit width and truncation (`<scroll>false</scroll>` truncates with "…").
  Long file names must be shown as the cleaned title or truncated. See ISSUE-101.

### 4.3 Colour

From `portrait.py` and `pages.py` (dark-only UI, matching iOS dark system colours):

| Token | Value | Use |
|---|---|---|
| `BG` | `FF000000` | page background |
| `SURFACE` | `FF1C1C1E` | grouped rows, cards |
| `SURFACE2` | `FF2C2C2E` | elevated surface, sheets, pressed state |
| `WHITE` | `FFFFFFFF` | primary text, glyphs |
| `GREY` | `99EBEBF5` | secondary text |
| `DIM` | `4DEBEBF5` | disabled or placeholder only |
| `SEP` | `33EBEBF5` | separators |
| `GREEN` | `FF30D158` | success, "done" |
| Blue accent | `FF0A84FF` (`pages.BLUE`), `FF4FA8FF` (`portrait.ACCENT`) | interactive tint only |
| `RED`, `ORANGE` | `FFFF453A`, `FFFF9F0A` | destructive, warnings |

Rules:

- Use colour to mean interactivity or status. Static decoration stays neutral. Have one or two tinted elements per view.
- Per-app colours (activity sheet bars) are allowed as small identifiers only, never as backgrounds behind text.
- **Known drift to resolve in a UI PR, not silently:** the project has two blues. Measured on `SURFACE2`,
  `0A84FF` small text reaches only 3.82:1, which is below 4.5:1, while `4FA8FF` reaches 5.56:1. Pick one accent
  per role (fills compared with small text) with the owner. Do not add a third.

### 4.4 Shape and surfaces

- Cards and posters: `RADIUS` = 26 (≈ 10 pt). Buttons and pills are capsules (radius = height/2, the `CAPSULES` texture sizes).
  Sheets use a visibly larger top-corner radius than cards. Reuse the radius of the existing sheet (Play on TV,
  activity sheet) rather than inventing a new one.
- Kodi rounds corners with pre-rendered masks/textures (`portrait.rounded()`, `coverage()`). These are circular
  arcs, not Apple's continuous corners. That is acceptable, but do not claim continuous corners.
- Depth comes from surface steps (`BG` → `SURFACE` → `SURFACE2`) and separators. Shadows are only for floating
  things (pill, sheet), and they should be soft.
- Glass-styled surfaces are only for floating functional chrome (pill, sheet header, overlay buttons), never for
  content cards (HIG `materials.md`: "Don't use Liquid Glass in the content layer").

### 4.5 Controls

- **Primary action:** white capsule with black text (`pill_button(..., 'primary')`). **Secondary:** glass-styled
  capsule with white text. Have one primary action per view.
- **Back/refresh:** `nav_button`, a bold chevron with no circle, inside a 150-unit touch area (ISSUE-099).
- Every tappable thing has a hit area of at least 118 × 118 units, even if the drawn glyph is smaller.
  Make the button bigger than the art, not the art bigger.
- Every gesture (swipe, long press) has an on-screen alternative. Every destructive action has a Cancel option.
- Focus state must be visible (dim or brighten). Kodi still has a focus model with keyboard and remote.

### 4.6 Motion

- Use Kodi `<animation>` with `tween="cubic"`/`"sine"` and `easing="out"`. Use 150–250 ms for state changes and
  250–350 ms for sheets and pill entry. Exit runs faster than entry and in the opposite direction.
- Motion explains a change (appear, move, dismiss). No looping decoration, apart from an indeterminate spinner
  while work is actually running.
- Do not animate anything over playing video except the controls appearing and disappearing.

### 4.7 Activity control (pill) and activity sheet

These are aesthetic rules. Behaviour belongs to PR #9:

- **Pill:** compact, floating, capsule. Have one line of text, and it must fit (§4.2). Show an app tile or ring with
  progress, plus a status glyph. Place it above the tab bar on tab pages. Hide it over alerts, the keyboard and
  sheets. It never covers playback controls. Its hit area must be at least 118 units tall.
- **Sheet:** use `SURFACE2` with the sheet top radius (§4.4) and a grabber. Have one row per job: title (one line,
  truncated), a status line (one line, truncated), and a thin progress bar in the app's colour. Pause/resume
  controls need 118-unit hit areas. The sheet's height follows its content up to a maximum, then scrolls.
- Progress wording is plain and short: "Preparing audio · 40 %". Do not repeat the same count ("8 remaining")
  twice in one row.

## 5. Platform behaviours to preserve

### 5.1 Touch and navigation

Preserve the tab bar order (Home · Movies · TV · Library · Search), back behaviour, long-press context menus,
whole-page show scrolling (ISSUE-100), the tap areas that route to modeless dialogs (PR #9), and the native
tab-bar ownership hand-off (`native_ui.py`). UI work must not change playback, AirPlay, gestures, Drive sign-in
or account flows unless that is the stated task.

### 5.2 Safe areas and orientation

The portrait canvas is already the safe area. Do not place content in the status-bar or home-indicator regions,
and keep the last row clear of the floating tab bar (`TAB_CLEAR`). Landscape occurs only during video or on an
external screen. Every portrait change must keep the landscape Fuse windows usable (they are generated
separately, and `OWN_1080I` keeps them out of portrait regeneration).

### 5.3 Accessibility and renderer limits

| Apple setting | Native tab bar (UIKit) | Kodi-drawn UI | Rule |
|---|---|---|---|
| Contrast (HIG: 4.5:1 for text up to 17 pt, 3:1 for 18 pt+ or bold) | system | **manual** | Measure every new text/background pair. Already measured: `GREY` on `BG`/`SURFACE`/`SURFACE2` gives 6.4/5.9/5.3:1, which passes. `DIM` gives 2.2–2.5:1, which **fails** for text. |
| Increase Contrast | system | not readable by Kodi today | Meet 4.5:1 without it. |
| Larger Text / Dynamic Type | system | **not supported** (fixed font sizes) | Never go below 30 units (11 pt). Allow wrapping or truncation. Kodi's own Skin Zoom setting is the only scaler. Record as a known gap. |
| Reduce Transparency | system adapts `UIGlassEffect` | **not readable** | Keep text-bearing glass-styled surfaces about 90 % or more opaque, so they work without the setting. |
| Reduce Motion | system | **not readable** | Keep Kodi animations short and non-essential. No parallax or zoom-to-fill effects. |
| VoiceOver | partial | **none** (Kodi is OpenGL) | Known platform gap. Don't claim VoiceOver support. |

A future native bridge could expose these settings to the skin, but that is a separate decision, not part of this policy.

### 5.4 Artwork and assets

Use artwork from the user's library or providers (TMDb, fanart) at runtime. Never commit film artwork, logos,
screenshots, Apple fonts or Apple marks. `scripts/check_project.py` rejects image files in the repository,
and textures are generated in code.

### 5.5 Icons

Kodi cannot render SF Symbols. Use the existing `special://skin/extras/icons/` set or the code-generated
textures. Match the weight and size of the existing glyphs (46 units in buttons, 104 for navigation glyphs). Only
the native bar uses SF Symbols.

## 6. Loading, empty and error states

- **Loading:** show the real structure immediately (cached posters, row titles), with a spinner only where
  something is genuinely pending. Never show a blank page with a spinner if cached content exists.
- **Empty:** say what is empty and what the person can do ("No downloaded movies yet: downloads appear here").
  Keep it distinct from "provider failed" (DEC-023).
- **Error:** say what failed, in plain words, with one recovery action. Raw exceptions, file paths and IDs go to the log, not the screen.
- Long-running work reports stage, percentage and what remains, in one non-overlapping line.

## 7. Required visual review process

For every UI change:

1. **Identify** the affected surfaces (windows/XML files, native views) and load the references from §3.
2. **State** the intended visual change in the plan or PR, and name the existing helpers and tokens you are reusing (§8).
3. **Implement** in the real technology (§2). Add no new colour, font size, radius or button variant
   unless the PR explains why the existing ones cannot work.
4. **Check** structure and regressions: `python3 -B scripts/check_project.py`, `python3 -B scripts/check_ui_guidance.py`,
   and the relevant suites (`test_portrait.py`, `test_pages.py`, `test_settings_page.py`, `test_notices.py`,
   `test_glassbar.py`, `test_native_ui.py`, and `test_activity.py` once PR #9 lands).
5. **Render and look:** capture screenshots where the environment allows it (Kodi rig: `scripts/portrait_rig.py`
   at 603 × 1167; browser for mockups). Inspect them for overlap, truncation, contrast, hit areas and alignment.
6. **Fix and repeat** steps 4–5 until clean.
7. **Report** what was verified, with which evidence class (§9), and what still needs review on the iPhone.

A passing XML check, test suite or build **does not establish visual quality**. If no render was possible, report
visual verification as **pending**.

## 8. Reuse before you create

Inspect these before writing new layout code. Extend them instead of adding near-duplicates:

- `portrait.py`: `FONTS`, colour tokens, `SIDE`/`GAP`/`RADIUS`/`POSTER`/`CARD`, `label`, `image`, `icon`, `surface`,
  `pill_button`, `circle_button`, `nav_button`, `page_header`, `tabbar`, `row`, `hero`, `poster_item`, `card_item`,
  `episode_item`, `centered_dialog`, `select_dialog`, texture generators (`rounded`, `glass`, `ring`, `gradient`, `fade`).
- `pages.py`: `page`, `back_header`, `row_layout`, `media_list`, `pill_button` (settings-style), `confirm_dialog`.
- `settings_page.py`: grouped settings rows.
- PR #9 (unmerged): `activity.py`, `activity_skin.py`, `IOSActivity.xml`, `Custom_1187_Activity.xml`.

**Known duplication:** `portrait.pill_button` and `pages.pill_button` are two capsule implementations. Prefer
consolidating to adding a third.
