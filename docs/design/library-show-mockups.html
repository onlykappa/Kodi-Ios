C · THE ••• MENU

A menu that belongs to the page

Why it failed: the show page is a full Kodi window opened from the Library dialog, and ••• opened Kodi's own context menu. Kodi then drew the window stack underneath (Home's artwork showed through) and the next tap landed on that hidden page, which took you out. The fix: the show page becomes a dialog (like the other Library pages) and the menu is drawn by the page itself, under the ••• button, with the page dimmed lightly behind it. A tap outside the menu closes only the menu.

How this would be built (after approval)

  • A: library_status drops the Ready rows; a summary card (status_ui.card) and two tiles reuse the Library page's counts and open Library › Movies / TV Shows. Needs you, Working now and Up next are unchanged.
  • B: library_show_page rows add the TMDb still (episode thumbnails already cached for the Library) and the episode title from the season cache (episode_minutes uses the same cache); the third number switches to "N not added" when there are problems. Repair keeps its id (9600+) but is drawn as an outlined capsule; after a tap the row reads the pending request at once.
  • C: IOSLibraryShow.xml becomes a dialog, and the ••• menu is a group inside it (ids 9800+), shown and hidden by a window property, with a full-screen tap catcher behind it that closes only the menu. Kodi's DialogContextMenu is no longer used here.
  • D: library_select_page reuses the show rows with a check, the season chips and a three-button toolbar (existing actions: Pick Better Versions, prepare again (retry), Delete with confirm).
  • Evidence after coding: desktop Kodi rig renders next to these boards; device proof needs the owner's iPhone.
