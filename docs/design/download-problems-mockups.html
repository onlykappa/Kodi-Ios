MOCKUP

Download problems

Owner (build 356): "we need a moc up of a better downloaded problems page as that is ugly!" Today it is a plain select list: "Retry All (2)" and "Clear All (64)" over 64 rows, some named by hash and every reason cut off. This replaces it with a real page in the Settings › Library style, the same page the bell's "Download problems" notice opens.

Evidence class: mockup (APPLE-UI-POLICY §9), not a Kodi render. Tokens from portrait.py / pages.py; posters are placeholder colour.

A · THE PAGE

What stopped, why, in plain words, and what to do

A summary first: what will try again by itself, what needs a new source, what you cancelled. Rows are grouped by what you can do about them, not by error text. Each row has a poster, the title (never a hash), one short reason and one action. One primary button: Retry. Copies already on Drive from another source are never listed.

Notes

  • Kodi skin XML, drawn with the existing helpers: Settings grouped rows and section headers, the Notifications segmented control, poster tiles from transfer_artwork, the white primary capsule and red text action. No new colours, radii or button styles.
  • Groups come from debrid_drive.problems(): "Can try again" (network, AllDebrid busy), "Need a new source" (no video, blocked, dead torrent), "Cancelled". Reasons are rewritten in plain words; the raw error stays in kodi.log.
  • Titles: the job title, else the cleaned file name, else "Unnamed download" (never a hash). Copies already finished from another source are not listed and are never retried.
  • Board E (P4, preparation problems): the Prepare filter and group come from the preparation queue (blocked or failed jobs), the same source Library status and the show page count, so the numbers always agree.
  • Numbers and names are examples; artwork is placeholder colour.
