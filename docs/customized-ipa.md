# Fully bundled Kodi iOS build

Owner approves one unsigned Kodi-iOS-Customized.ipa; manual ZIP import is superseded. Build status/checksum/artifact will be recorded after actual CI.

The validated import contents are reused internally as build inputs, not an owner import task. Sources and dependencies are placed in AppData/AppHome/addons beside the foundation addons. Kodi's system addon-manifest registers them as optional packaged addons, initially enabled on fresh profiles and still disableable. A packaged Python service copies the sanitized profile seed once using actual special://profile. Unknown private addon settings remain; replaced files and GUI preferences are journaled privately. Live guisettings.xml is never replaced: Kodi Settings APIs apply preferences and select Fuse after registration/configuration. Completed startup does not reapply on later launches, preserving owner edits. Existing disabled dependencies may need API activation, recorded for recovery. No native executable/engine injection or extra entitlement is added.

The service stops on hash/path/registration/API failure, restores journaled files and requests Estuary, records incomplete API recovery honestly, and reports a setup error. Interrupted setup is recovered on a later launch rather than silently claimed successful. Program addon Kodi iOS Automatic Setup and Recovery offers explicit recovery to pre-setup files and Estuary. Actual UI availability and API recovery still require phone tests. Keep the original diagnostic IPA (SHA-256 8d20fcc260aebcd11dee8e5c7f2807ec7c0ef24f528fd58ab43e58ba7ea8f212) as a separate fallback file. Do not uninstall an existing working Kodi app to update it; uninstalling can erase its container/backups. The signer controls actual update/container behavior.

Expected owner procedure: download the completed IPA artifact, extract the outer GitHub ZIP, sign every native image using the existing sideloader, install, launch and wait for automatic setup/skin activation; if Kodi shows its normal Keep Skin confirmation, tap Yes within ten seconds; authorize Google Drive privately when needed. The bootstrap verifies the loaded skin rather than assuming API acceptance proves activation. No ZIP import, Files-app setup, private profile export or file copying is required. Existing phone account settings are preserved where present; absent/expired accounts may still require their provider's authorization. No saved Deck tokens or personal media are bundled.

Elementum engine, Umbrella, YouTube/Fusion and broken sports remain unavailable/deferred as previously approved. Retained YouTube trailer controls may be unavailable. Google Drive uses the previously approved maintainer OAuth relay; authentication and playback are not host-certified. All 184 screenshot requirements and actual phone signing/startup/touch/Drive/restart/rollback testing remain outstanding. No Phase 5, merge or release.
